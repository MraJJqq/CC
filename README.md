# VEGAS CC — A-share

CC is a standalone A-share page built from the seven-system source snapshot in `MraJJqq/Media/V6`, with A-share market data and signal generation adapted from the existing CCN implementation.

## Seven systems
1. K-line renderer and Vegas EMA overlay — Media V6 renderer, connected to Tencent QFQ daily candles.
2. Shared viewport and gestures — Media V6 viewport/gesture behavior with a CC-specific persistence namespace.
3. Rolling market cards — Media V6 card presentation and interaction, populated from the A-share CN500 snapshot and latest-session signals.
4. Logo and countdown — Media V6 logo module adapted to display the selected A-share name/code and daily interval.
5. Timeframe selector — Media V6 selector shell, fixed to the A-share daily interval (1D).
6. Signal feed and bottom ticker — Media V6 ticker presentation, connected to the A-share daily signal payload.
7. Full-screen dynamic layout — Media V6 viewport/safe-area/orientation system with an A-share panel geometry layer.

## A-share data
- Market universe: the existing CN500 code list.
- Historical candles: Tencent via AKShare `stock_zh_a_hist_tx`, QFQ daily data.
- Stock names: Tencent quote-name endpoint.
- Incremental cache: per-symbol compressed history with a 14-calendar-day overlap.
- Signal warm-up: at least 676 valid daily bars; EMA periods 12, 36, 43, 144, 169, 576, 676.
- Scan only the last completed A-share trading session; do not publish partial results when Tencent history fetches fail.
- Pages data is generated by the scheduled/manual A-share workflow. No credentials are committed.

## Runtime boundaries
- CC is independent. Browser cache and viewport keys use CC-specific namespaces.
- Media remains the source of truth for the seven shared systems and visual assets.
- Tencent is the only configured A-share historical data source in this project.
- The A-share scan and Bark notification run only through the existing scheduled/manual workflow. Ordinary source commits do not send notifications.
